# Cross-cutting metrics of a review

Step 5 of `SKILL.md` runs the deterministic scans and then computes the metrics. The first section gives the command, the output format, and the test that turns a row into a finding for each scan. The second section gives the target of each metric.

## Deterministic scans

### Glyph and dash tells: `scan_glyphs.py`

Run `python3 "<skill-dir>/../../scripts/scan_glyphs.py" <paper-file> [<input.tex> ...]` over the paper file(s). Each stdout line is `<file>:<line>:<col>\t<glyph-name>\t<context>` for one tell, with `em-dash`, `ascii-dash`, `en-dash`, `arrow`, `curly-quote`, `ellipsis`, and `nbsp` as the categories, and the stderr summary gives the per-category totals (e.g. `15 tell(s) [em-dash=15 ascii-dash=0 ...]`). Take the dash-density count in step 5 of `SKILL.md` from this output, not from a visual estimate, adding the `em-dash` and `ascii-dash` rows. Report every `em-dash`, `arrow`, `curly-quote`, `ellipsis`, and `nbsp` row as a per-section finding with its ASCII replacement. For `en-dash`, keep the dashes in numeric or page ranges (`pp. 12–18`). For any glyph, skip the occurrences inside quoted source material or a code string. A glyph inside a code *comment* is still a finding (the comment is prose). An `ascii-dash` row is a candidate for the per-mark judgment in **Em-dashes** (`G.em-dashes`), not an automatic finding: `---` is the correct em-dash in LaTeX and `--` is a normal ASCII dash in Markdown, so report one only when the dash itself is the wrong mark. The ASCII dash pass already skips flags, numeric ranges, table separators, fenced blocks, inline code, `%` comments in `.tex` (so the ` -- ` separator in the `% GROUNDING:` comments that the bundle writes never counts), and runs of four or more dashes. The Unicode glyph rows skip none of these, so clear a glyph inside fenced code or a `% GROUNDING` quote by hand. The script exits 0 once it read a file (with or without findings) and 2 on a usage error.

### Reference candidates: `scan_reference.py`

Run `python3 "<skill-dir>/../../scripts/scan_reference.py" <paper-file> [<input.tex> ...]`. Each stdout line is `<file>:<line>:<col>\t<kind>\t<context>` for one candidate: `bare-demonstrative` (a sentence-initial *This*, *These*, *That*, or *It* followed directly by a verb), `bare-quantifier` (a sentence-initial *Both*, *Neither*, *Either*, *Each*, *None*, *All*, *Some*, *Most*, *Several*, *Many*, or *Few* followed directly by a verb), `such-noun` (*such* + noun), or `stand-in` (*ones*, *the former / the latter*, *respectively*, *do so*, *those of / that / which / with*). The stderr summary gives the per-kind totals. The rows are candidates, not findings. Apply the tests of the **Reference** rules to each (identifying the referent for `bare-demonstrative` and `such-noun`, attaching the noun for `bare-quantifier` unless an exception in `G.bare-quantifiers` applies, and putting the noun back for `stand-in`), report the confirmed rows as per-section findings under that rule (or under author judgment when the referent cannot be determined, per step 4 of `SKILL.md`), and clear a dummy *it* that the script did not filter. First-mention definites are not scanned. Check them in the per-section pass. The script exits 0 once it read a file and 2 on a usage error.

### Repeated sentences: `scan_repeats.py`

Run `python3 "<skill-dir>/../../scripts/scan_repeats.py" <paper-file> [<input.tex> ...]`, or, for a PDF, run it on the extracted text saved as a `.txt` file in a temporary directory. Each stdout line is `<file>:<line>:<col>\trepeat\t<context>` for a sentence that repeats text from an earlier sentence of the same file, and the context gives the line of the earlier sentence (`line 25 | ...`). The scan lists a verbatim copy, a copy with a changed ending, and a short sentence pasted twice, and it leaves out a sentence that recurs word for word three or more times, such as a template label. The rows are candidates for **Refer back instead of repeating** (`G.refer-back`). Apply the test in the rule to each: a brief reminder that the argument needs stays, and a verbatim or near-verbatim copy is a second copy and a finding, located at the later sentence, with a pointer back to the first as the suggested revision. Clear a row inside quoted source material or form text. The script exits 0 once it read a file and 2 on a usage error.

### Cross-reference candidates (LaTeX only): `scan_crossrefs.py`

Run `python3 "<skill-dir>/../../scripts/scan_crossrefs.py" <root.tex>` over the LaTeX root. The script follows `\input` / `\include` itself and resolves labels and references across all files of the paper. Each stdout line is `<file>:<line>:<col>\t<kind>\t<context>` for one candidate: `unreferenced-float` (a figure or table with no label, or with no label that a reference names, located at its `\begin` line, with the labels and the start of the caption as context), `lowercase-ref` (a lowercase name such as *section* or *fig.* before a reference that prints no name), `name-before-autoref` (a name before `\autoref`, `\cref`, `\Cref`, or `\zcref`, which print the name themselves, so the output reads "Section Section 3"), and `hard-coded-ref` (a name followed by a typed number, or "Appendix A"). The stderr summary gives the per-kind totals. The rows are candidates. Report a confirmed `lowercase-ref` row as a per-section finding under **Capitalize cross-references** (`S.capitalize-cross-references`) with the capitalized name as the suggested revision, and a confirmed `name-before-autoref` row as a per-section finding under **Use cross-reference macros** (`L.cross-reference-macros`) with the doubled name removed. Report a `hard-coded-ref` row as a finding under `L.cross-reference-macros` with a `\ref{}` to the label that the number stands for when that label is identifiable, list it under **Items requiring author judgment** otherwise, and clear it when it points to the section or table of another work. For a confirmed `unreferenced-float` under **Refer to every figure and table in the text** (`S.refer-to-every-figure`), look for a sentence that already discusses the content of the float. If one does and the float has a label, report a per-section finding that adds the reference to that sentence, as in "... (Table~\ref{tab:usage})". Otherwise list the float under **Items requiring author judgment**, since only the author can write the sentence that discusses it or decide to remove it. In the **Cross-references (LaTeX only)** block of the report, list each confirmed row by location, pointing to its finding or author-judgment item rather than repeating it. The scan skips `%` comments, `\iffalse` blocks, and verbatim and listing environments, so it lists a float that only commented-out text references. The script exits 0 once it read a file and 2 on a usage error.

### Sentence candidates (STE mode only): `scan_sentences.py`

Run `python3 "<skill-dir>/../../scripts/scan_sentences.py" <paper-file> [<input.tex> ...]`, or, for a PDF, run it on the extracted text saved as a `.txt` file in a temporary directory. Each stdout line is `<file>:<line>:<col>\t<kind>\t<context>` for one candidate, and the context opens with the word count or the matched words. The kinds are `long-sentence` (more than 25 words, with a quotation, code span, or URL counted as one word), `uniform-run` (three or more consecutive sentences within 5 words of each other in length), `passive`, and `nominalization` (a light verb followed by an action noun). The stderr summary gives the sentence count and the per-kind totals. The rows are candidates. Apply the STE rules' tests to each: split a sentence of more than 35 words, apply the clause test of `T.short-sentences` to a sentence of 26 to 35 words, vary a run, keep a passive only when its actor is unknown, and keep a noun that names a thing rather than an action. Report the confirmed rows as per-section findings. In STE mode, take the sentence-length variance count in step 5 of `SKILL.md` from the `uniform-run` rows. The script exits 0 once it read a file and 2 on a usage error.

## Metrics

- Dash density, counting `em-dash` and `ascii-dash` rows together (target: ≤ 2 to 3 per page-equivalent of ~350 words, matching the em-dash ceiling in the general layer, with the count taken from `scan_glyphs.py`).
- Colon density in running prose (target: ≤ 2 per page-equivalent).
- Capitalization after a colon in running prose (flag a colon when the clause after it is a complete sentence beginning lowercase, except the first item of an enumerated series of independent clauses, which the capitalization rule treats as a list and keeps lowercase, and flag a colon when the text after it is a fragment or list beginning uppercase).
- Semicolon density in running prose (target: ≤ 1 to 2 per page-equivalent).
- Combined pause-punctuation signal (the combined em-dash + colon + semicolon count per page-equivalent, where a page near all three caps at once is over-punctuated).
- Restricted-word density per paragraph (flag paragraphs with more than 2 to 3 occurrences).
- Sentence-length variance (flag stretches of three or more consecutive sentences within 5 words of each other in length).
- Verb-tense compliance, checked per clause, not per section (only when the scientific layer is in scope). Do not certify a section from its dominant tense. A present-tense prior-work clause can hide inside an otherwise-correct section. Inspect every sentence with a citation or author name as its subject (`\citeauthor{...}`, "X et al.", "the authors"). An empirical action that the cited study performed takes past or present perfect (compare against the table in the scientific layer).
- American-vs-British spelling (flag British variants).
- "Significant" audit (flag non-statistical uses).
- STE metrics (only in STE mode): sentences over 35 words, sentences of 26 to 35 words that fail the clause test, runs of similar length, passives with a known actor, nominalizations, and units with more than one stylistic device (`T.one-device`).
